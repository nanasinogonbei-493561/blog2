## 修正した問題

| 観点 | 問題 | 修正 |
| --- | --- | --- |
| 集計の正確さ | メール収集・1回制限なしでは同一人物の複数送信を確実に区別できないのに、人数として数えていた | 設定を明示し、集計単位を回答件数に統一。回答内の重複と別送信の重複を区別 |
| 未回答の扱い | 任意質問が空欄の場合の分母が曖昧だった | 質問別に回答のある件数を分母とし、空欄を別記。空欄を「困っていない」とみなさない |
| 質問設計 | 頻度は過去3か月、体験や負担は時期を指定していなかった | 質問3・5・6も過去3か月に統一。「期間内に困っていない」「覚えていない」を区別 |
| 根拠の区別 | 体験から推測した原因を「分かった困り事」と断定していた | 表を「困り事の仮説」に変更し、追加の聞き取りで確認すると明記 |
| 検証の範囲 | 初回の操作確認と継続利用の検証がつながっていなかった | 初回で分かることを操作のしやすさに限定。実際の返却機会後に再利用を確認する手順を追加 |
| 回答の管理 | 保管期限は示していたが、フォームとシートの削除が別である説明がなかった | 権限確認と削除対象を双方に明記 |
| SEO・読みやすさ | タイトルがアイデア発見だけを示し、本文の試作手順が伝わりにくかった | 「Googleフォームで自作アプリを考える方法｜アンケートの質問例から試作まで」に変更。slugは維持 |
| AIO・読みやすさ | 調査数の目安が独立した根拠のある基準に見える可能性があった | 件数の疑問に見出しと直答を置き、10〜20件は記事内で提案する区切り例だと明記 |
| 冗長さ | 同一記事への誘導が導入と末尾で重複していた | 導入の自然な関連記事リンクを残し、末尾の重複を削除。説明を整理 |
| 画像表示 | 画像の縦横寸法がHTMLに未指定だった | 実ファイルで確認した1536×1024を日英各6画像へ指定 |
